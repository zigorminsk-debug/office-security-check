# Архитектура приложения «Аудит защиты»

## Обзор

Приложение построено по модульному принципу: движок сканирования, база знаний
уязвимостей, аудит хоста, формирование отчётов и графический интерфейс полностью
разделены. Пакеты движка (`scanner`, `vuln`, `netutil`, `report`, `hostcheck`, `model`)
не зависят от GUI и могут использоваться из CLI, тестов и интеграций.

```
┌──────────────┐     ┌──────────────────────────────────────────────┐
│   ui (Fyne)  │────▶│                scanner.Engine                │
│  или main.go │     │ discovery → portscan → fingerprint → probes  │
└──────┬───────┘     └──────────────────┬───────────────────────────┘
       │                                │ []model.Host ([]Service)
       │                                ▼
       │                     ┌────────────────────┐
       │                     │   vuln (KB+rules)  │▶ []model.Finding
       │                     └─────────┬──────────┘
       │                               ▼
       │                     ┌────────────────────┐
       └────────────────────▶│ report (HTML/JSON/ │
                             │ CSV) + score       │
                             └────────────────────┘
```

## Пакеты

| Пакет | Назначение |
|---|---|
| `internal/model` | Общие типы: `Finding`, `Service`, `Host`, `ScanConfig`, `Report`, `CheckResult`, уровни опасности и категории риска |
| `internal/netutil` | Разбор целей (IP/CIDR/диапазоны), портов, TCP-подключения с тайм-аутом, `RateLimiter` |
| `internal/scanner` | Движок сканирования: обнаружение хостов, параллельный TCP-скан, баннер-граббинг, фингерпринтинг, протокольные проверки |
| `internal/vuln` | База знаний (сигнатуры версий → CVE), эвристические правила экспозиции, движок сопоставления, скоринг |
| `internal/hostcheck` | Проверки защищённости локального Windows-хоста (PowerShell, реестр) |
| `internal/report` | Сборка отчёта и запись в HTML/JSON/CSV |
| `internal/ui` | Графический интерфейс Fyne v2 |

## Движок сканирования (`scanner.Engine`)

Четыре фазы, каждая — с обратным вызовом прогресса и отменой через `context`:

1. **Discovery** — TCP-ping по ключевым портам (445, 443, 80, 135, 22, 139, 3389, 8080…),
   обратный DNS, косвенное определение ОС по набору служб.
2. **Port scan** — параллельный TCP connect-scan: пул воркеров (`Workers`, по умолчанию 256),
   `RateLimiter` (token bucket) для ограничения скорости, прогресс в процентах.
3. **Probes** — для каждого открытого порта набор протокольных проверок
   (см. [CHECKS.md](CHECKS.md)): баннер, TLS, HTTP, SMB, RDP, Redis/Mongo/ES, и т.д.
   Результаты складываются в `Service.Extra` (флаги), `Service.TLS`, `Service.HTTP`.
4. **UDP** (глубокий профиль) — SNMP, DNS, TFTP, NTP.

### Протокольные проверки (сигнатурные, без эксплуатации)

- **SMB**: мультипротокольный NEGOTIATE (диалект SMB1/2/3), отдельный NEGOTIATE
  `NT LM 0.12` (детект SMBv1), `SecurityMode` (обязательное подписывание),
  анонимная сессия + TREE CONNECT к `IPC$`, **TRANS_PEEK_NMPIPE** (статус
  `STATUS_INSUFFICIENT_RESOURCES` = уязвим MS17-010 / EternalBlue).
- **RDP**: X.224 Connection Request + RDP Negotiation Request → выбранный протокол
  (0x00 = без NLA, 0x02/0x08 = CredSSP/Hybrid).
- **TLS**: рукопожатие `crypto/tls` (сертификат, версия, шифр) + **raw ClientHello**
  для проверки TLS 1.0/1.1/1.2, слабых шифров и **Heartbleed**
  (запрос heartbeat с завышенной длиной полезной нагрузки).
- **HTTP**: заголовки безопасности, опасные пути, WebDAV (PROPFIND), TRACE,
  открытый прокси (CONNECT), панели администрирования по маркерам.
- **Хранилища данных**: PING для Redis, OP_QUERY `isMaster` для MongoDB,
  GET `/` для Elasticsearch/CouchDB/Docker/K8s/kubelet/etcd, `stats` для Memcached,
  MQTT CONNECT без учётных данных, AMQP handshake.
- **UDP**: SNMPv1 GET с community `public` (BER), DNS-запрос с RD (открытый резолвер),
  TFTP RRQ, NTP-версия.

## База знаний (`vuln`)

1. **Сигнатуры версий** (`Signatures`): продукт + диапазон версий → CVE, CVSS,
   категория риска, рекомендация. Сравнение версий — по числовым сегментам
   (`CompareVersions`, `NormalizeVersion`).
2. **Правила экспозиции** (`ExposureRules`): эвристические условия поверх
   `Service.Extra`/`TLS`/`HTTP` (например, `rdp_nla == "false"` → критическая находка).
3. **Категории риска** — наследуемая из модели:
   `Заражение вирусами`, `Несанкционированный доступ`, `Шифрование данных (вымогатель)`,
   `Укрепление защиты`, `Информация`.
4. **Скоринг**: `ScoreFindings` — штрафы Critical=25 (×CVSS/10), High=10, Medium=4, Low=1;
   итог = `max(0, 100 − Σштрафов)`.

## Аудит хоста (`hostcheck`)

Единый файл с проверками, описанными декларативно (`checkDef`: скрипт PowerShell +
функция оценки вывода). На не-Windows возвращается результат «пропущено».
Проваленные проверки автоматически превращаются в находки (`vuln.FindingsFromChecks`).

## Отчёты (`report`)

`report.Build` собирает `model.Report` (конфигурация, хосты, находки, аудит, счётчики,
балл). Запись — в файл (`WriteJSON/HTML/CSV`) или в поток (`Write*To` — используется
диалогом сохранения GUI).

## Графический интерфейс (`ui`)

Fyne v2.7: вкладки «Уязвимости», «Хосты и службы», «Аудит хоста», «Журнал».
Сканирование выполняется в горутине; **все** обновления виджетов идут через `fyne.Do`
(главный поток UI). Остановка — через `context.CancelFunc`.

## Потокобезопасность

- Сканер: горутины + `sync.Mutex` на аккумуляторы результатов, семафоры на
  количество одновременных соединений.
- UI: состояние таблиц изменяется только на главном потоке (внутри `fyne.Do`).
